# EIP-712 on a Ledger: what the device really displays

> **Note.** `docs/LIMITS.md`, cited below, is not included in this repository.

This document tells a single experiment, carried through to the end, and what it taught. Everything
that follows was observed — the commands that reproduce it are at the end.

---

## 1. Why the number has to be on the device

TARE's guard intercepts a Uniswap v4 swap **before** the signature and announces what the pool's
hook takes. If that number only appears in the page, it proves nothing: a page repaints itself.
Malware that controls the tab also controls the figure displayed.

**The only place where a number commits to anything is the hardware wallet's screen.**
It is a screen the browser cannot reach.

Hence the question: can **our** fields be displayed on a Ledger — not a generic transaction, but
`take 689.95 bps`?

---

## 2. The message

An EIP-712 whose every field is a finding of the guard. Primary type `TareGuardApproval`:

```
verdict          BLOCK
hook             0x1aEA38f06deCE45c252eF1Ac5AF989D51Dc8E8cc
poolId           0xD996FF76787C7C520483FE0164699395CC89BFCB6FC4BDBA282…
take             689.95 bps
label            MEASURED
size             100000000000000 en entree
direction        1->0
measuredAtBlock  50614000
dataset          125072 mesures, 112 hooks, 7817 pools, chaine 8453,
                 moteur tare-engine/0.3.0, stub 0x8e39b2ad…
freshness        mesures au bloc 50614000 ; bloc courant non fourni, retard inconnu
warnings         aucun
promptDigest     0x7CA143E05DC7F4A9A27E22CD8A8ABDF95A20B090601D17599D…
```

Three choices deserve an explanation.

**`take` is a string, not a number.** `689.95 bps` with its unit, because a `uint` on a Nano
screen does not say whether it is basis points, hundredths, or wei.

**`label` travels with the value.** A `take` without its label would let one believe that an
absence of measurement is worth zero. On the device as elsewhere, `NOT_MEASURABLE` is not `0.00`.

**`promptDigest` seals the text shown to the human.** The signature does not only attest to the
fields: it attests to **the exact sentence** the guard displayed.

## 3. The experiment

Not a physical device: **Speculos**, the emulator Ledger publishes precisely for this, running the
**official Ethereum application 1.22.3** for Nano X, downloaded from the releases of
`LedgerHQ/app-ethereum`. Same binary, same display code.

The transport connects. The device answers `getAddress`:
`0xDad77910DbDFdE764fC21FCD4E74D71bBACA6D8D`.

### First attempt — the wall

With `fullImplem: true`, which asks for the **filtered** display path:

> **Blind signing must be enabled in settings**

Status `0x6a80`, *invalid data received*.

The application can only label the fields of an arbitrary EIP-712 if it holds **filter
descriptors** for that schema — the clear-signing metadata that Ledger publishes per message
type. `TareGuardApproval` is ours, Ledger has never seen it.

### The trap

The on-screen instruction says to enable **Blind signing**. It is the wrong setting, and enabling
it would have destroyed exactly what we were looking for: blind signing makes you sign **a hash**,
with no field at all.

Our code refuses that path. `packages/guard/src/ledger.ts:20`: **no**
`signEIP712HashedMessage` **fallback**. A guard that fails into "yes" guards nothing.

### The right setting

Going through the application's settings, screen by screen:

```
Blind signing     Enable transaction blind signing        Disabled
Nonce             Display nonce in transactions           Disabled
Raw messages      Displays raw content of EIP712 messages Disabled   <---
Debug contracts   Display contract data details           Disabled
Smart accounts    Enable EIP-7702 authorizations          Disabled
```

**"Raw messages"** — enabled, and with `fullImplem: false`, the device displays **sixteen screens**:

```

poolId (1/2) 0xD996FF76787C7C52 0483FE0164699395CC 89BFCB6FC4BDBA282
poolId (2/2) 0771F127FA300
take 689.95 bps
label MEASURED
size 100000000000000 en entree
direction 1->0
dataset (1/3) 125072 mesures, 112 hooks, 7817 pools, chaine 8453, moteur
dataset (2/3) tare-engine/0.3.0, stub 0x8e39b2ad4344342
dataset (3/3) b4f7dc5cf31df0aec9b d5b5f8ec7fccd241256 cf1fda637a4
measuredAtBlock 50614000
freshness (1/2) mesures au bloc 50614000 ; bloc courant non fourni,
```

**Signature returned: `v=28`.** The raw, untouched capture is in
[`docs/ledger/ECRANS.md`](docs/ledger/ECRANS.md).

## 4. What this proves, and what it does not prove

**Proven.** The typed message reaches the device, the device displays **every field labelled**, a
human reads `take 689.95 bps` on a screen the page does not control, and the signature is
cryptographically real.

**Not proven.** No physical device. Speculos runs the same binary and the same display code —
that is why Ledger publishes it — but an emulator is not a Nano in a hand.
And above all: our production transport is **WebHID**, whereas Speculos goes through
HTTP/APDU. The `openWebHidDevice` path is therefore **not** exercised. About ten lines that ten
minutes with a real device would cover.

---

## 5. The gap, and it fits in one sentence

The default setting is a defensible choice: not displaying just any raw EIP-712 protects the
ordinary user.

**What is not defensible is the instruction.** A developer who runs into *"Blind signing must be
enabled in settings"* enables blind signing, gets a hash on the screen, and concludes that clear
signing is unavailable for custom schemas. **It is available.** The message sends them to the
wrong button, and nothing in it mentions "Raw messages".

This will be true for every security tool that wants its figures on the device rather than in
the page — that is to say, for all of them.

**The proposed contribution is a sentence to fix, not a feature to build**:
when an EIP-712 cannot go through the filtered path, say so, and name **Raw messages**
as the setting that displays it raw. `app-ethereum` for the screen text, `ledgerjs` to surface
the cause instead of a bare `0x6a80`.

**NOT VERIFIED, and deliberately not asserted**: we have not gone through the procedure for
submitting descriptors to Ledger, so we do not describe it.

What **Speculos** lacked: nothing. It emulated faithfully, exposed the screens over HTTP, and let
the buttons be driven. It is thanks to it that all of this is stated instead of being assumed.

## 6. Reproduce

```bash
curl -sL https://github.com/LedgerHQ/app-ethereum/releases/download/1.22.3/app-1.22.3-nanox.elf \
  -o eth.elf
docker run -d --name speculos -p 5010:5000 -v "$PWD":/apps \
  ghcr.io/ledgerhq/speculos:latest --model nanox --display headless --api-port 5000 /apps/eth.elf

# Settings -> Raw messages -> Enabled: press, read, decide
curl -s  "http://127.0.0.1:5010/events?currentscreenonly=true"
curl -sX POST http://127.0.0.1:5010/button/right -d '{"action":"press-and-release"}'

cd packages/guard && npm i --no-save @ledgerhq/hw-transport-node-speculos-http
# then: buildGuardTypedData(report) -> eth.signEIP712Message(path, typed, false)
```

`fullImplem: false` is decisive. `true` asks for the filtered path — the one that has no
descriptors for our schema, and that produces the misleading message.
