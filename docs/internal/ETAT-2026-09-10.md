## 1. The offer, as it is built

**For whom.** Someone about to swap a token on Base. Not the liquidity provider —
that is the difference from LPLens, and it is carried by the product, not by the pitch.

**The question.** "You put in €100, how much do you get back?" The round trip, in both directions.

**Why nobody else answers it.** The identity of a v4 pool — its `PoolKey` — **contains**
the hook's address. "The same pool without its hook" cannot be addressed. TARE does not change the key:
it changes **the code**. On a Base fork pinned at block 50,614,000, `anvil_setCode` replaces the
hook's bytecode with an inert 89-byte stub. Same `poolId`, same liquidity, same `slot0`,
byte for byte. We quote twice. The difference is the toll.

**What we sell.** Not the data — the 125,072 measurements are public and versioned. The right to
run the machine on a pool nobody has measured: 0.001 USDC per unit, settled in x402
on Hedera.

# SECOND SESSION OF 10 SEPTEMBER — the audit, and what it found

A **17-agent** mega-audit across 8 dimensions (permit2, account, wired keys, front end,
proofs, deployment, consistency, submission) returned ~100 confirmed findings and **7 refuted**.
What follows is what was fixed afterwards, in order of severity.

## 8. The five defects that would have cost real money

### 8.1 The substitution went in the WRONG DIRECTION

`memeSens()` in `alternative.ts` was hard-coded to "buy the token" and **ignored the
direction of the requested swap**. On a real pair from the corpus — pool `0x997673…` at 300.00 bps and its
sibling `0xe11e1e…` at 0.0316, same currencies and same hook — someone **selling** their
token for ETH received a transaction that **spent ETH to buy the token**.

A second defect of the same family: sibling gates were looked up by **token**, so a
TOKEN/WETH pool was compared with a TOKEN/USDC pool "at the same size" — 1e18 units of one
against 1e18 units of the other.

Fixed by `sensEquivalent()`: a gate is comparable only if it performs **exactly the
same swap**, same two currencies, same direction. Found by a test of the new HTTP route.

### 8.2 Three hand-written selectors, all wrong

In `apps/web/src/compte/api.ts`: `abonner()` was `0x30ff4dce`, not what was written.
A wrong selector does not fall through to `receive()` — which is only called on **empty**
calldata — it **reverts**: every subscription attempt would have burned the user's gas.
Verified against a local anvil. The site no longer sends any calldata.

Worse: `prix()` and `duree()` carried two more invented values, **under a comment
claiming they had been verified with `cast sig`**. A claim of a verification that was never done prevents anyone from looking for it.
The real ones are `0xc65e9c79` and `0x541a629d`.

### 8.3 The Permit2 nonce was fabricated when the read failed

`autorisationDuRouteur` at `null` — so **not read** — produced a permit with nonce 0. Permit2
requires the exact nonce and refuses with a revert, **at send time**. The user signed a
seemingly valid message and lost their gas. New state `NONCE_NON_LU`.

### 8.4 The substitution went out with no output floor

`amountOutMinimum` and the `minAmount` of `TAKE_ALL` were set to **zero**: a transaction
signable at any price, the written invitation to a sandwich. And the default deadline
was `0xffffffff` — **7 February 2106**.

The floor CANNOT come from the corpus, pinned at block 50,614,000: a quote that is
six days old is wrong in both directions. It comes from a **live** quote, or there is no
transaction. Nine named states in `envoi.ts`.

### 8.5 Caddy's CORS blocked the whole account

`authorization` and `x-tare-cle` were not in `Allow-Headers`, `DELETE` not in
`Allow-Methods`: the browser did **not even** send the requests — failure at preflight,
with a CORS error as the only clue.

## 11. The operational defects fixed

- the Postgres pool was not listening for `'error'`: **a database restart killed the whole
  process**, including the routes that never touch it;
- the `migre` flag stayed true after the database was lost;
- `?limite=abc` returned a **silent 500** — `Number("abc")` is NaN, NaN goes through
  `Math.min`/`Math.max` intact and ends up in a SQL `LIMIT`;
- `POST /compte/journal` checked the key but **never the subscription**: a key issued
  once could write for life. The refusal is non-destructive and says so;
- `app.onError` / `app.notFound`: every failure came out as `Internal Server Error` in
  `text/plain`, unreadable for a client that parses JSON;
- `tsx` was a devDependency that `npm ci --omit=dev` skips, and the `CMD` ran `npx tsx`:
  the image **downloaded tsx from npm on every start**;
- `docker-compose.deploy.yml` shipped no Postgres and did not start the assistant;
- `deploy.sh` printed the next steps as if everything were fine even when the API had never
  answered. It now fails with the logs of the five services;
- without `VITE_TARE_API`, the published site showed "127.0.0.1 unreachable" to a visitor — which
  reads as "this site is broken". It now says "no API published for this version".

## 13. Gate A4 finally writes to disk

It is the only place in the project where a **quote** becomes an **executed swap** — so the only
proof that the entire corpus, which is made of quotes, matches what really happens. And
it was the only result that wrote nothing: "9 pools, 8 matching to the wei, 1 divergent"
existed only in prose. A proof that is not written down is not a proof, it is a memory.

`python3 -m tare.gates.a4 --write` writes `docs/dataset/porte-a4.json` and **appends** to
`porte-a4.jsonl` — append-only, because an overwritten file would lose the previous runs.

Replayed against the fork on 10 September, on 3 executed pools (14 tried, 3 not playable by the
generic probe):

| hook | size | quoted | executed | |
|---|---|---|---|---|
| `0x588c683ecc45` | 1e12 | 100.0936 | 100.0936 | matches to the wei |
| `0x92708e7d3b91` | 1e19 | **3.5669** | **0.0** | **diverges** |
| `0x2aa659040c4c` | 1e12 | 280.0 | 280.0 | matches to the wei |

The divergence of pool `0x92708e7d…` is reproduced, dated and signed by a replay command.
It says something precise: on this pool, at this size, the **3.5669 bps that the
quote announces do not materialise at execution**. It is a fact against us, and it is
exactly the kind of fact this project exists to publish.

The page was at **13.99 KB against a ceiling of 14** — one byte of margin. Fixing the section

claimed 14 KB are corrected. 0.3 KB costs three milliseconds; a false headline costs for as
long as the page is online. The budget exists to protect the first paint, not

`metering`, `x402-client` — with the message "dependencies are missing: run
install-all.sh", when it had just succeeded. Each tool pointed to the other: the kind of
dead end that takes an hour to untangle.

There was nothing to untangle. **I had launched `install-all.sh` while the tests
were running on the same clone**, and `npm ci` deletes `node_modules` before reinstalling. The
three suites running at that moment crashed for lack of modules.

Verified by removing the table and re-running `metering` alone: 49 tests green, table absent.
So it was not the table, it was me. I nearly published a repo defect that was a
measurement-protocol error — in a project whose argument is that a badly conducted reading
does not amount to a result.


### Twenty honesty tests that were disappearing from the count

Found while looking for why the clone returned 332 engine tests and the local copy 356. The answer
was not "the clone has fewer" — it was **`raise unittest.SkipTest` in `setUpClass`**.

That form does print its message, and the intent was explicitly good: the
comment said *"it must SAY so and name the command, not blow up on a missing
file. A judge who clones deserves a sentence, not a stack trace."* But the class then returns
**`Ran 0`**: the tests are counted **neither as passed, nor as skipped**. They
disappear.

Two classes, twenty-four tests:

| class | tests | prerequisite missing from a clone |
|---|---|---|
| `test_rag.TestEnTete` | 12 | `graph.json`, 198 MB |
| `test_rag.TestStoreRefuse` | 8 | Postgres + pgvector |
| `test_graph.TestCacheBench` | 4 | `graph.json` |

And `scripts/test-all.sh` announced **"engine 332/332"** — a count that reads as *complete*
when twenty-four tests had not run. It is the exact pattern this project refuses
everywhere else: **an absence reported as a complete result.** In its own
test report, for the third time — the two previous ones are documented in
`vitest_count` in the same file.

`@unittest.skipUnless` on the **class** marks each method as skipped: it goes into
`testsRun` and into the "tests skipped" line of the report. The clone now returns **57/57 with
15 skipped** for `test_graph` and **47/47 with 26 skipped** for `test_rag`, instead of 53 and
27 silent.

The message stays the same. It is the count that stopped lying.
